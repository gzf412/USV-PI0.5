# 红色圆形浮标 200 回合采集

此处的“200 条”是 **200 个任务成功且独立通过轨迹平顺性与当前示范标准检查的回合**，每个回合包含连续的图像、33 维艇状态、自然语言指令、左右连续推力以及两路回看视频。任务成功但反复转向、明显停走或缺少有效质量证明的回合不计入有效数据。采集期间保留失败尝试供排查；整批验收完成后归档小型元数据并删除失败和被替换尝试的原始数据、图片及视频。

当前批次为 `outputs/episodes/red_round_200_20261027/`，200 条已验收，包含 60,505 个决策样本、6,030.5 秒仿真跨度和 400 份视频，按完整回合划分为 160 条训练、40 条验证。2026-10-28 重采的20条沿岸回合见 [SHORE_REVIEW.md](../outputs/episodes/red_round_200_20261027/SHORE_REVIEW.md)；最新40条复杂障碍回合的实际角度、航程、逐门验收和视频见 [COMPLEX_REVIEW.md](../outputs/episodes/red_round_200_20261027/COMPLEX_REVIEW.md)。当前汇总见 [STANDARD_REVIEW.md](../outputs/episodes/red_round_200_20261027/STANDARD_REVIEW.md)。

以下命令均在 `usv_vla_project` 根目录执行。平顺性检查方法和阈值见 [trajectory_quality.md](trajectory_quality.md)。

| 场景 | 成功回合数 |
| --- | ---: |
| 可视目标接近并停下 | 50 |
| 初始在摄像机视场外、仍位于艇前方的目标 | 30 |
| 从指定圆筒左边经过后接近目标（包括连续绕行） | 30 |
| 从指定圆筒右边经过后接近目标（包括连续绕行） | 30 |
| 从两个圆筒之间经过后接近目标（含初始偏角） | 40 |
| 沿岸前进并接近目标 | 20 |

地图只包含一个红色圆形浮标以及 1–4 个圆筒；穿过两筒的任务至少有两个圆筒。场景生成器改变起点、航向、距离和圆筒布局，要求绕行或穿行的指定圆筒在初始相机图像中。任务使用反馈控制生成连续推力，数据保留真实发布的左右推力，不靠复制回合或扰动已采轨迹扩充。

## 运行

当前批次已完整通过验收。复杂替换后的有效路径以 `manifest.json` 和 `splits/` 为准。下方汇总命令可以重新核对完整数据；采集新批次请使用新的输出目录及对应计划，避免覆盖当前批次。

每回合记录前向相机 10 Hz、空中相机 5 Hz，JPEG 质量 90。两份 MP4 均按共同的仿真时间轴生成，空中画面只供检查，不进入模型观测。

批采集按固定10Hz源时刻因果选取已经到达的原始传感器数据，不插值图像或动作。每行保存目标源时刻、决策开始时已知的最新仿真时钟及两者偏差，最多允许50ms；超过预算则本次失败，不补造漏掉的控制帧。推力发布另存`action_publish_monotonic_ns`墙钟时间，该时钟偏差不等于精确的仿真推力执行时间，也不表示实际发布无抖动。

接受一个回合需要任务成功、原始记录有效、退出时发布零推力并停止仿真、时间因果和全部引用图像审计通过、两份 MP4 实际完整解码且帧数和元数据一致。还会核对该回合与不可变计划的哈希、一个红色圆形浮标与 1–4 圆筒布局、实际第一帧艇姿态下的目标与圆筒可见性、严格 10 Hz 决策时间轴；非零推力始终同一个值的回合会被拒绝。`batch_acceptance.json` 保留采集源码指纹和左右推力的不同指令数量、标准差、峰值、饱和占比。

此外，每个回合必须独立通过 `smooth_trajectory_v1`。检查器从原始 `steps.jsonl` 计算航向累计变化、显著往返纠偏、角速度/角加速度、速度加速度/jerk、非终止推力变化率及中途低速和速度谷。它按初始朝向、计划路径区分必要转弯与多余回摆；目标初始出画所需的一次大转弯不会仅因累计转角大而被拒绝。直达、穿筒/沿岸与绕筒使用不同的航向预算，绕筒的速度谷目前作为诊断指标。原始记录不会被滤波、插帧或修改以通过检查。

所有 `kind=approach` 的回合还要检查冲过停车范围后再倒退的情况：艇体前向速度 `u < -0.03 m/s`，或全程最小目标距离低于 `stop_min_m - 0.03 m`，会被拒绝。这里为微小的稳态调整或仿真噪声保留容差；负推力用于减速不等同于艇已倒车，判定看实际 `u`。最终任务仍须满足原来的停车距离范围。

控制器采用连续前视路径跟踪和yaw阻尼，接近终点时按整条路径的剩余弧长提前减速；不再等切换到很短的末航段后才开始刹停。这用于减少短末段冲过停车位置、再倒退纠正的情况，是否合格仍由独立检查器从实际轨迹判断。

现有单筒绕行回合使用 `early_alignment_v1`，按实际记录的姿态检查绕行时齐平角度和起步转角。新增连续绕行依据各门逐一检查侧别、顺序、退出通道、齐平角度和保守净距；新增穿筒按实际过门和两指定圆筒净距检查，详见 [复杂任务复查](../outputs/episodes/red_round_200_20261027/COMPLEX_REVIEW.md)。长沿岸回合依据岸线碰撞网格对每个记录姿态进行距离检查。

质量证明保存在 `batch_acceptance.json` 的 `trajectory_quality` 中，包含 profile、阈值、实际指标、原始 `steps.jsonl` 和 `episode.json` 的 SHA256，以及检查器实现的 SHA256。汇总会重新从原始文件计算，并核对证明；缺证明、证明与现有轨迹/检查器不符或计算失败均不能列为有效回合。

同一文件的 `navigation_standard` 保存 `early_alignment_v1` 的速度与实际齐平检查，以及原始轨迹和回合元数据的 SHA256。整批收尾还会逐条重算并完整核对该证明，不能沿用其他回合或旧轨迹的通过标记。

这些是当前平静水面仿真的筛选参数，没有经过实艇标定。本次平顺性验收**没有改变任务原有停车语义**：完成路线后进入距浮标 1.9–2.3 米的范围，速度不超过 0.2 m/s 并持续 2 秒。它表示低速停留，不能解释为严格静止或长时间定点保持。

单个场景默认最多尝试 3 次；`--max-attempts` 表示包含此前记录的总次数，不是额外新增次数。用完后记为失败，不会静默以复制数据凑数。启用 `--stop-on-quality-failure` 后，新质量失败会先暂停，不会自动重复同样的失败轨迹。磁盘剩余低于 3 GiB 时停止启动新回合，已有数据和进度保留。用 Ctrl+C 可请求停止当前采集，待记录器归零并停止仿真后退出。记录器超过墙钟上限仍不退出时，批处理请求其停止并暂停整个批次，检查仿真进程后再恢复，避免重叠启动。

80% 场景标记 `train`、20% 标记 `validation`，即 160/40 回合。后续导出和训练时按整个场景回合划分，避免同一个回合的相邻帧同时进入训练集和验证集。此脚本只采集和检查数据，不执行微调。

可以单独只读检查某条轨迹，命令输出 JSON 证明；这不会代替任务、因果和视频审计，也不会自动写入采集验收证明：

```bash
PYTHONPATH=src /usr/bin/python3 -m usv_vla.trajectory_quality \
  outputs/episodes/red_round_200_20261027/episode_0003_around_left/attempt_01
```

收齐后汇总实际数据并生成有效回合清单：

```bash
PYTHONPATH=src /usr/bin/python3 -m usv_vla.summarize_collection \
  outputs/episodes/red_round_200_20261027 --require-complete
```

汇总只有在 **200 条轨迹的任务、平顺性和证明核对全部通过**、六类配额与 160/40 分组正确且无其他问题时才写入 `complete`。`--require-complete` 会在未完成或存在问题时返回非零退出码；不能用物理任务成功数代替质量通过数。

批根的 `README.md` 提供可用类别的示例视频链接，并在存在时链接 `QUALITY_REVIEW.md`。`collection_summary.json` 记录实际决策样本数、场景分布、推力统计、时间延迟、轨迹唯一性、平顺性通过数、失败/待证明列表和指标分布。`splits/accepted_episodes.txt`、`train_episodes.txt`、`validation_episodes.txt` 只列出同时通过所有检查的当前有效尝试。后续应使用清单中的路径，不能把整个目录下的全部 `attempt`、失败记录或 `superseded` 旧示范当作训练数据。

旧批次及被替换轨迹的原始数据已清理，计划及审计元数据保留。历史清理证据 [finalized_standard_collection_20261027.json](../reports/finalized_standard_collection_20261027.json) 记录的是沿岸及复杂障碍替换前的快照，不代表当前数据集；以 manifest 和当前汇总为准。

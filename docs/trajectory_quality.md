# 轨迹平顺性验收

任务完成不代表示范适合训练。艇可以最终通过指定圆筒并停在目标范围内，但中途仍可能反复左右纠偏、为追逐航点不断减速再加速，或产生突变推力。`smooth_trajectory_v1` 是独立于任务评分的质量检查，直接读取每回合的原始 `episode.json` 与 `steps.jsonl`，不修改或平滑原始数据。

这些阈值针对当前平静水面的仿真场景，没有经过实艇标定。碰撞净距、路线完成、相机有效性、传感器因果对齐与视频完整性仍由原有审计检查，不能用平顺性通过替代。

当前数据为 `outputs/episodes/red_round_200_20261027/` 中重新采集的完整200回合。共有60,505个决策样本和400份视频，训练/验证按整回合划分为160/40；其中20条沿岸回合已按更长、更靠岸的标准重采，另有40条复杂障碍任务替换旧示范。单筒任务适用 `early_alignment_v1`，连续绕行还需逐门独立复核。

## 必要转弯与反复纠偏

目标初始在摄像头外时，船需要先做一次明显转向；绕筒也可能需要先偏向一侧再回到目标方向。因此不能对所有任务使用同一个“累计转角不得超过多少度”的规则。

检查器按实际连续航向计算累计绝对转角，按初始朝向、计划航点和最终停止位置计算计划转角预算。显著往返纠偏采用角度滞回和 0.5 秒持续时间判断，避免把微小抖动当成一次转向。

| 任务组 | 航向变化预算 | 显著往返纠偏限制 |
| --- | --- | --- |
| 直接接近，目标画内或画外 | 累计绝对转角减去首尾净转角，最多 3° | 3°滞回下不允许显著反向纠偏 |
| 两筒之间穿行、沿岸前进 | 累计转角最多为计划转角加 15° | 3°滞回下最多一次反向 |
| 从圆筒左侧或右侧绕行 | 累计转角最多为计划转角加 45° | 10°滞回下不超过计划转向符号反转次数与 1 的较大值 |

计划中不足 1° 的转角不参与转向符号反转计数。一次持续的必要大转弯可以通过；直达任务中反复偏左、偏右，即使最后回到正确位置，也会被拒绝。

## 速度、推力与中途停走

计算使用 10 Hz 原始决策时间轴，航向取 `pose_xyzrpy[5]`，艇体速度与yaw速率取 `state[0:3]`，左右推力取 `action`。当前 profile 的主要限值为：

| 指标 | 仿真筛选限值 |
| --- | ---: |
| 决策间隔 | 0.1 秒，容差 1 微秒 |
| yaw速率绝对峰值 | 0.45 rad/s |
| yaw加速度绝对峰值 | 0.5 rad/s² |
| 速度加速度绝对峰值 | 0.7 m/s² |
| 速度jerk绝对峰值 | 2.5 m/s³ |
| 非终止推力变化率绝对峰值 | 10.1 N/s |

控制器的推力变化率目标为 10 N/s，检查器保留小量数值余量。最终 `done` 行的终止推力转换从这项slew统计中单独排除并记录，仍需满足原任务的终止归零要求。

当船曾达到 0.25 m/s、且距目标仍大于 3.5 米时，连续低于 0.12 m/s 超过 1 秒会被判为中途低速停走，避免把起步和最终接近减速误判为异常。

速度谷检查用于发现“先明显降速、随后又加速”的航点追逐现象。它在上述航行区间内使用 5 个原始样本的均值作诊断，比较谷值前后各 3.5 秒内的速度峰值；谷深以两个峰值中较低者减去谷值计算。直接接近、穿筒和沿岸任务中，谷深超过 0.12 m/s，或超过计划巡航速度的 30%，均会拒绝。绕筒任务的速度谷目前仅记录诊断值，但仍执行持续低速、加速度、jerk 和航向检查。诊断均值不会写回数据，也不会改变动作或图像。

## 冲过停车范围与倒退

对任务类型 `kind=approach` 的所有回合，包括绕筒、穿筒或沿岸后接近浮标的任务，还检查实际运动而不仅是最终是否到位：

- 全程艇体前向速度的最小值 `u < -0.03 m/s` 时拒绝，防止把明显倒退纠正当成正常前向接近。
- 全程最小目标距离低于 `stop_min_m - 0.03 m` 时拒绝，防止冲入停车距离内侧后再退回合格位置。当前 `stop_min_m=1.9`，对应低于 1.87 米拒绝。

这两项为微小的稳态调整或仿真噪声保留容差，不要求每个样本的 `u` 都严格非负。负推力可用于正常制动，不能仅根据动作正负判断艇是否倒车。距离容差也不放宽原任务的最终停车范围，终点仍需满足 1.9–2.3 米要求。

控制器已按整条路径的剩余弧长提前限制期望速度，并继续使用连续前视目标与yaw阻尼。这样即使最后一个路径航段很短，也能在进入末段前逐步减速，减少冲过停车位置再倒退的现象。控制器修改本身不是验收证明；仍需由检查器重新读取实际轨迹判定。

## 绕筒时提前回正

`early_alignment_v1` 在上述平顺性检查之外，限定当前示范的速度与绕筒姿态。巡航设定为 `min(原巡航速度 × 1.5, 0.75)` m/s；绕单筒阶段的速度上限另限制为约0.5435685 m/s，转弯或接近停车位置时仍按实际需要减速。

绕行曲线在圆筒门线处的规划切线与原航路平行。检查器 `collection_standard.py` 读取原始位置、航向与门线几何，在两个实际样本之间插值门线穿越时刻，独立检查：

- 与圆筒齐平时，相对原航路的航向偏角绝对值不超过10°。
- 从起步至齐平，船头相对起始方向的向外转角峰值不超过35°。

规划曲线符合要求不能代替实际姿态达标；通行侧、净空、退出通道及最终停车仍需完成原任务验收。当前60条左右绕筒回合的齐平偏角绝对值最大约8.09°、平均约2.21°，初始向外转角最大约34.13°，见[当前标准复查](../outputs/episodes/red_round_200_20261027/STANDARD_REVIEW.md)。

## 证明绑定与有效清单

批采集先通过任务、因果、路线、布局、图像和完整视频解码审计，再调用独立质量检查。通过结果保存在 `batch_acceptance.json` 的 `trajectory_quality` 字段中，包含：

- `profile`、`passed`、`issues` 和实际使用的 `thresholds`。
- 航向、速度、推力指标与计划路线参考值。
- 原始 `steps.jsonl` 和 `episode.json` 的 SHA256。
- `trajectory_quality.py` 检查器实现的 SHA256。

汇总会对每个当前 accepted 回合重新读取原始数据计算质量，核对保存证明中的阈值、指标与指纹。检查器或原始文件改变后，旧证明不能继续沿用，必须重新完成审计。仅有旧的任务成功记录、缺失质量证明、证明过期或实际轨迹未通过检查，都不能进入训练清单。

`batch_acceptance.json` 的 `navigation_standard` 同时保存 `early_alignment_v1` 的实测结果及原始 `steps.jsonl`、`episode.json` 的SHA256。整批收尾逐条重算并完整比较200份证明，全部通过才允许清理旧数据；单纯的 `smooth_trajectory_v1` 通过标记不能代替这项提前回正检查。

采集排查期间使用新的尝试目录，不覆盖前一次轨迹。整批200条全部验收通过后，失败和被替换（`superseded`）尝试的原始数据、图片与视频已删除，仅归档小型诊断元数据，并在manifest尝试记录中保留 `directory_removed` 清理标记。即使历史 `summary.json` 写着 `success: true`，也不能当成有效示范。训练和导出只使用当前汇总生成的 `splits/accepted_episodes.txt`、`train_episodes.txt` 与 `validation_episodes.txt`。

`collection_summary.json` 只有在 200 个回合同时通过任务与质量验收、证明核对正确、六类配额和 160/40 分组满足要求且无其他问题时才会标记 `complete`。其中 `smoothness_passed_count`、失败/待证明列表和指标分布来自当次实际检查结果，不按旧的成功数量推断。

## 命令

以下命令在项目根目录运行。单条质量检查是只读操作，输出 JSON，未通过时返回非零退出码；它不会自动写入批采集证明，也不能代替其他审计：

```bash
PYTHONPATH=src /usr/bin/python3 -m usv_vla.trajectory_quality \
  outputs/episodes/red_round_200_20261027/episode_0003_around_left/attempt_01
```

恢复或复查当前已存在的完整批次：

```bash
bash scripts/sim.sh collect --resume \
  --output-root outputs/episodes/red_round_200_20261027
```

恢复时重新核对已有accepted回合，符合任务、平顺性及其声明的示范标准的回合会跳过。`--max-attempts` 包含此前尝试次数，不是额外新增次数；默认值为3。

启用 `--stop-on-quality-failure` 后，新尝试一旦被独立平顺性检查拒绝，批处理会保存 `batch_failure.json`、尝试状态和进度，然后立即暂停整个批次。先检查失败视频、轨迹和控制器原因再恢复，避免使用相同控制器重复耗光次数。指定其他批次时同时传入 `--output-root /绝对路径/批目录`。恢复时仍会复查已有 accepted 回合，质量不合格的旧尝试会被替换，新示范须重新独立验收。

汇总并要求整个批次验收完成：

```bash
PYTHONPATH=src /usr/bin/python3 -m usv_vla.summarize_collection \
  outputs/episodes/red_round_200_20261027 --require-complete
```

汇总会更新有效清单和报告。存在未完成项或审计问题时返回非零退出码，不能把部分数据报告称为完整 200 条。采集过程和文件结构见 [batch_collection.md](batch_collection.md)。

完整收尾检查会先运行上述汇总，再独立核对全部提前回正证明。默认仅检查和列出清理计划；只有显式 `--apply` 才归档小型元数据、删除固定的旧数据目录和本批失败尝试。2026-10-27 的[收尾报告](../reports/finalized_standard_collection_20261027.json)是后续沿岸和复杂障碍替换前的历史快照，不代表当前数据集；当前证明以 manifest 和批次汇总为准。

## 停车任务保持原定义

本次质量检查没有修改原来的 1.9–2.3 米目标距离、速度不超过 0.2 m/s 并持续 2 秒的任务判定。它仍是仿真中的低速停留要求，允许少量前移；不能据此宣称严格静止或长时间定点保持。实际停车质量需要结合轨迹、末段速度和两路视频继续检查。
